= 既存仮想マシンの移行

== はじめに

このラボのこのセクションでは、https://docs.redhat.com/en/documentation/migration_toolkit_for_virtualization/2.8/[Migration Toolkit for Virtualization^] (MTV) を使用して、VMware vSphereからOpenShiftに仮想マシンをインポートします。移行ツールキットは2つの「モード」のインポートをサポートしています：

* コールドマイグレーションは、移行を開始する前にソース仮想マシンをシャットダウンします。これはデフォルトの移行タイプです。
* ウォームマイグレーションは、ソース仮想マシンが実行されている間にデータをコピーします。大部分のデータが移行されたら、VMがシャットダウンされ、最終的なデータが宛先にコピーされます。その後、新しいVMを起動でき、VM上でホストされるアプリケーションのダウンタイム期間がはるかに短くなります。

NOTE: 移行ツールキットは、OperatorHubで利用可能なOperatorを使用してクラスターにすでにデプロイされています。

Operatorのインストールと構成方法に関するドキュメントはhttps://docs.redhat.com/en/documentation/migration_toolkit_for_virtualization/2.8/html/installing_and_using_the_migration_toolkit_for_virtualization/installing-the-operator_mtv[こちら^]にあります。

Migration Toolkit for Virtualizationを自分のニーズに合わせて構成する方法についてさらに詳しく知りたい場合は、以下のリンクのドキュメントを参照してください：

* https://docs.redhat.com/en/documentation/migration_toolkit_for_virtualization/2.8/html/installing_and_using_the_migration_toolkit_for_virtualization/prerequisites_mtv#openstack-prerequisites_mtv[OpenStack^]
* https://docs.redhat.com/en/documentation/migration_toolkit_for_virtualization/2.8/html/installing_and_using_the_migration_toolkit_for_virtualization/prerequisites_mtv#rhv-prerequisites_mtv[Red Hat Virtualization^]
* https://docs.redhat.com/en/documentation/migration_toolkit_for_virtualization/2.8/html/installing_and_using_the_migration_toolkit_for_virtualization/prerequisites_mtv#vmware-prerequisites_mtv[VMware vSphere^]

.*目標*

* VMware vSphere環境を探索する
* Migration Toolkit for Virtualization（MTV）の構成を確認する
* 移行計画を作成する
* VMをOpenShift Virtualizationに移行する
* 組み込みインタラクティブデモで高度なオプションを探索する

[[prerequisites]]
== 移行の前提条件

以下の前提条件がすべての移行に適用されます：

* ISO イメージと CD-ROM ディスクはマウント解除する必要があります。
* 各NICには、IPv4アドレスまたはIPv6アドレスが含まれていますが、NICは両方を使用できます。
* VM オペレーティングシステムは、OpenShift Virtualizationのゲストオペレーティングシステムとして使用するために、https://access.redhat.com/articles/4234591[認定されてサポートされている^]必要があります。
* VM名には、小文字（a-z）、数字（0-9）、またはハイフン（-）のみを含める必要があり、最大253文字です。最初と最後の文字は英数字である必要があります。名前に大文字、スペース、ピリオド（.）、または特殊文字を含めることはできません。
* VM名は、OpenShift Virtualization環境内の既存VMの名前と重複してはいけません。

NOTE: *Migration Toolkit for Virtualization* は、要件に準拠していないVMに自動的に新しい名前を割り当てます。これにより、移行を問題なく進めることができます。

[[migrating_vms]]
== VMwareから仮想マシンを移行する

3階層アプリケーションがVMware上にデプロイされており、OpenShiftに移行していただきます。

このアプリケーションは、以下の4つの仮想マシンで構成されています：

* Webサーバーへのトラフィックをリダイレクトする1つのHAproxyシステム。
* MariaDBデータベースを実行する1つのLinuxシステム。
* PHPアプリケーションをホストし、データベースに接続する2つのMicrosoft Windowsサーバー。

このラボでは、3つの4つの仮想マシンをコールドマイグレーションを使用して移行するよう求められます。

NOTE: OpenShiftがSDNに接続されたVMのネットワークトラフィックとロードバランシングを *Service* を使用してネイティブに処理するため、HAproxy（ロードバランサー）VM を移行する必要はありません。

== 高度な機能のインタラクティブデモ

ラボのコールドマイグレーションが完了するのを待つ間に、それらの仮想マシンを使用して操作できるようになるまで、Migration Toolkit for Virtualizationで実行できるいくつかの追加の高度な移行オプションを紹介する機会がありました。このセクションでは、移行プロセス中の仮想マシンの自動再構成、およびダウンタイムを削減するウォームマイグレーションの実行方法について説明する予定です。

このセクションを確認していただき、インタラクティブなデモビデオをお楽しみください。

=== 自動化構成フック

自動化構成フックは、Migration Toolkit for Virtualizationに組み込まれた本当に素晴らしい強力な機能です。

構成フックは、Migration Toolkit for Virtualizationの機能として含まれています。移行プロセスの前後に仮想マシンのプロパティを変更するため、移行前フックまたは移行後フックとしてセットアップできます。これらはAnsibleオートメーションの力を活用して、YAML形式のプレイブックを通じて目的のアクションを実行しますが、https://www.redhat.com/en/hybrid-cloud-solutions/automation?sc_cid=RHCTN0250000435827&gad_source=1&gad_campaignid=20322566154&gbraid=0AAAAADsbVMRTUlnZMtmJPEadK_tiBW92m&gclid=EAIaIQobChMIqt2m1oHxjAMVjnFHAR1rXhMLEAAYASAAEgIdAfD_BwE&gclsrc=aw.ds[Ansible Automation Platform^]の個別のサブスクリプションは必要ありません。代わりに、移行プロセス中にターゲット仮想マシンに対して提供されたプレイブックを実行する別の *ansible-runner* ポッドの実行内で実行されます。

これらの自動化されたタスクは、ソースハイパーバイザーで機能した仮想マシンがOpenShift Virtualizationで期待どおりに機能するようにするために非常に価値があります。

ゲスト上のファイルの編集やハードウェアデバイスの構成の更新など、より複雑なタスクなど、簡単なタスクを実行できます。

以下のインタラクティブデモをチェックして、両方の例の動作を確認してください。

.デモのステップには以下が含まれます：
* リモートESXiホスト上の仮想マシンを検出し、コールドマイグレーション計画を構成します。
* 移行前フックを使用して、ネットワークアダプターをVMware ネイティブ形式からOpenShift VirtualizationのVirtIO形式に再構成し、移行プロセスの開始時刻をタイムスタンプするテキストファイルを書き込みます。
* 移行後フックを使用して、ネットワークアダプターの構成をクリーンアップし、別のテキストファイルを記述して移行プロセスの完了をタイムスタンプします。
* 実行中の仮想マシンがが正常に移行され、スタートアップ後に行った変更が続行されることを確認します。

=== ウォームマイグレーション

Migration Toolkit for Virtualizationのデフォルトの移行タイプはコールドマイグレーションですが、移行ウィンドウ全体でソース仮想マシンを電源オフにすることが必要な場合、長期間のダウンタイムを維持できない貴重なワークロードを持つ多くの組織があります。このようなワークロードの場合、Migration Toolkit for Virtualizationはウォームマイグレーションもサポートしています。

ウォームマイグレーションプロセスは、ソースハイパーバイザーのChanged Block Tracking（CBT）テクノロジーを活用して実現されます。これはバックアップおよびディザスターリカバリー操作でよく使用されており、操作中にネットワーク経由で転送されるデータ量を削減します。VM上でCBTが有効になると、スナップショットが定期的に取得されて、VMディスク上の変更のレコードが保持されます。VМを移行する時が来たら、初期ゲストのコピーは実行中に転送され、ダウンタイムなしで大量のマシンデータを転送することが可能になります。停止ウィンドウがスケジュール可能な場合、Migration Toolkit for Virtualizationはカットオーバーをトリガーします。これはゲストを電源オフにし、変更されたCBTスナップショットデータを転送し、VMの低いダウンタイムが必要です。

.デモのステップには以下が含まれます：
* ソースハイパーバイザーで実行中のWindowsおよびLinux仮想マシンを探索します。
* Migration Toolkit for Virtualizationプロバイダーの構成を確認します。
* ウォームマイグレーション計画を作成して実行し、カットオーバーフェーズで停止します。
* ゲストがまだ実行されていることを確認した後、カットオーバー操作を初期化します。
* 移行計画が完了した後、環境を探索します。

== まとめ

このセクションでは、Migration Toolkit for Virtualizationを探索し、VMware vSphere環境からOpenShift Virtualizationへの既存の仮想マシンの移行を支援するためにそれを使用しました。また、特定の移行シナリオで使用できるいくつかの高度な機能を実装できるインタラクティブなビデオも参照しました。

Migration Toolkit for Virtualizationに加えて、現在利用可能な他の2つの移行ツールキットがあります。これらの組み合わせを使用して、多くの種類のワークロードを組織のニーズに応じてOpenShiftクラスター内および間で移動できます。

* https://docs.redhat.com/en/documentation/migration_toolkit_for_applications/7.2/html/introduction_to_the_migration_toolkit_for_applications/index[Migration Toolkit for Applications^] - 大規模なアプリケーション最新化作業をコンテナーとKubernetesに加速します。
* https://docs.redhat.com/en/documentation/openshift_container_platform/4.18/html/migration_toolkit_for_containers/about-mtc[Migration Toolkit for Containers^] - OpenShiftクラスター間でステートフルアプリケーションワークロードを移行します。

これらの他の移行ツールキットの詳細については、Red Hatアカウントチームにお問い合わせください。
