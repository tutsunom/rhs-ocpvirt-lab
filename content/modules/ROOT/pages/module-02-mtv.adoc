= 既存仮想マシンの移行

== はじめに

このセクションでは、 https://docs.redhat.com/en/documentation/migration_toolkit_for_virtualization/2.8[Migration Toolkit for Virtualization^]  (MTV) を使用して、VMware vSphere から OpenShift へ仮想マシンをインポートします。MTV は、以下の 2 つのインポートモードをサポートしています：

* **コールドマイグレーション**: 移行開始前にソース VM をシャットダウンします。これがデフォルトの移行タイプです。
* **ウォームマイグレーション**: ソース VM を実行したままデータをコピーします。データの大部分が転送された後、VM を一時的にシャットダウンして最終的な差分データをコピーします。新しい VM の起動までのダウンタイムを大幅に短縮できます。

NOTE: MTV は、OperatorHub の Operator を使用してクラスターへ構成済みです。

Operator のインストールや構成に関する詳細は、 https://docs.redhat.com/en/documentation/migration_toolkit_for_virtualization/2.8/html/installing_and_using_the_migration_toolkit_for_virtualization/installing-the-operator_mtv[公式ドキュメント^] を参照してください。

また、各プラットフォーム向けの構成要件については以下のリンクを参照してください：

* https://docs.redhat.com/en/documentation/migration_toolkit_for_virtualization/2.8/html/installing_and_using_the_migration_toolkit_for_virtualization/prerequisites_mtv#openstack-prerequisites_mtv[OpenStack^]
* https://docs.redhat.com/en/documentation/migration_toolkit_for_virtualization/2.8/html/installing_and_using_the_migration_toolkit_for_virtualization/prerequisites_mtv#rhv-prerequisites_mtv[Red Hat Virtualization^]
* https://docs.redhat.com/en/documentation/migration_toolkit_for_virtualization/2.8/html/installing_and_using_the_migration_toolkit_for_virtualization/prerequisites_mtv#vmware-prerequisites_mtv[VMware vSphere^]

.*目標*

* VMware vSphere 環境を確認する
* Migration Toolkit for Virtualization (MTV) の構成を確認する
* 移行計画 (Migration Plan) を作成する
* VM を OpenShift Virtualization へ移行する
* 高度なオプション（インタラクティブデモ）を学習する

[[prerequisites]]
== 移行の前提条件

すべての移行において、以下の前提条件を満たす必要があります：

* ISO イメージおよび CD-ROM ディスクはアンマウントされていること。
* 各 NIC に IPv4 または IPv6 アドレスが割り当てられていること（両方の使用も可能）。
* VM の OS が OpenShift Virtualization のゲスト OS として https://access.redhat.com/articles/4234591[認定・サポート^] されていること。
* VM 名は小文字（a-z）、数字（0-9）、ハイフン（-）のみを使用し、最大 253 文字以内であること。また、最初と最後の文字は英数字である必要があります。
* VM 名が OpenShift Virtualization 環境内の既存の VM と重複していないこと。

NOTE: MTV は、命名規則に準拠していない VM に対して自動的に新しい名前を割り当て、移行を継続できるようにします。

[[migrating_vms]]
== VMware から仮想マシンを移行する

VMware 上にデプロイされている 3 階層アプリケーションを OpenShift へ移行します。

このアプリケーションは、以下の 4 台の仮想マシンで構成されています：

* **HAproxy**: Web サーバーへのトラフィックを振り分けるロードバランサー。
* **MariaDB**: Linux 上で動作するデータベースサーバー。
* **Microsoft Windows サーバー (2台)**: PHP アプリケーションをホストし、データベースに接続。

このラボでは、これら 4 台のうち 3 台の仮想マシンをコールドマイグレーションで移行します。

NOTE: HAproxy (ロードバランサー) は、OpenShift ネイティブの *Service* 機能で代替可能なため、今回の移行対象には含まれません。

=== VMware 環境の確認

移行元（ソース）環境のリソース（データストアやポートグループ）が、OpenShift 側のストレージクラスやネットワーク設定にどのようにマッピングされるかを理解するために、まず vSphere 側を確認します。

. VMware vCenter にログインします: https://{vcenter_console}[vCenter Console^]
. *Launch vSphere Client* をクリックします。
. 以下の認証情報を使用します:
- *ユーザー:* {vcenter_full_user}
- *パスワード:* {vcenter_password}

. ログイン直後、インベントリツリーの上部で「権限がありません」というメッセージが表示される場合がありますが、これは現在のユーザーアカウントにおける想定通りの挙動です。

. *Workloads* アイコンをクリックし、*Roadshow* フォルダ配下の 4 台の VM を確認します。

=== MTV における VMware プロバイダーの確認

vSphere 環境の確認が終わったら、OpenShift ウェブコンソールに戻ります。

NOTE: MTV は OpenShift Virtualization とは独立したツールのため、*仮想化 (Virtualization)* パースペクティブからはアクセスできません。

. 左メニューのパースペクティブ選択から *管理者 (Administrator)* を選択します。
+
image::2025_spring/module-02-mtv/05_Admin_Persona.png[link=self, window=blank, width=100%]

. 左メニューの *Migration* -> *Providers for virtualization* へ移動します。

. プロジェクト選択で *mtv-{user}* を選択します。
+
image::2025_spring/module-02-mtv/06_MTV_Providers.png[link=self, window=blank, width=100%]

NOTE: MTV 2.4 以降、管理者権限がなくてもアプリケーションチームに移行作業を委任できるようになりました。

デフォルトでは、ターゲットとなる OpenShift Virtualization を示す *host* プロバイダーと、今回接続した VMware vSphere クラスターを示す *vmware* プロバイダーが構成されています。

=== 移行計画の作成

次に、どの VM をどのように移行するかを定義する *移行計画 (Migration Plan)* を作成します。

. *Migration* -> *Plans for virtualization* に移動し、*Create Plan* をクリックします。
+
image::2025_summer/module-02-mtv/07_Create_VMWARE_Plan.png[link=self, window=blank, width=100%]

. *Plan name* に `move-webapp-vmware` と入力します。プロジェクトが `mtv-{user}` であることを確認し、ソースプロバイダーとして *vmware* を選択します。
+
image::2025_summer/module-02-mtv/08_VMware_Source_Provider.png[link=self, window=blank, width=100%]

. ユーザーアカウント `{user}` がアクセス可能な VM のリストが表示されます。
+
image::2025_summer/module-02-mtv/09_VM_List.png[link=self, window=blank, width=100%]

. 以下の 3 台を選択し、*Next* をクリックします：
* database-{user}
* winweb01-{user}
* winweb02-{user}
+
image::2025_summer/module-02-mtv/10_VM_Select_VMWARE_Plan.png[link=self, window=blank, width=100%]

. 移行先の設定画面が表示されます。適切なターゲットとマッピングを指定してください：
* *Target provider*: host
* *Target namespace*: vmexamples-{user}
* *Network map*: Pod Networking
* *Storage map*: ocs-storagecluster-ceph-rbd
+
NOTE: ネットワークとストレージのマッピングが自動検出されない場合は、上記の値を選択してください。

. *Create migration plan* ボタンをクリックします。
+
image::2025_summer/module-02-mtv/11_Create_Migration_Plan.png[link=self, window=blank, width=100%]

. 計画の検証が開始され、ステータスに「Not Ready」と表示されます。
+
image::2025_summer/module-02-mtv/12_Migration_Plan_Unready.png[link=self, window=blank, width=100%]

. ステータスが *Ready* に変わったら、青色の *Start* ボタンをクリックして移行を開始します。

image::2025_summer/module-02-mtv/13_Migration_Plan_Ready.png[link=self, window=blank, width=100%]

. 確認ダイアログで再度 *Start* をクリックします。
+
image::2025_summer/module-02-mtv/14_Confirm_Migrate_Start.png[link=self, window=blank, width=100%]

. ステータスが *Running* になり、進捗状況（％）が表示されます。
+
image::2025_summer/module-02-mtv/15_VMs_Migrating.png[link=self, window=blank, width=100%]

. *Virtual Machines* タブで、詳細な進捗状況を確認できます。
+
image::2025_summer/module-02-mtv/16_VMs_Migrating_Details.png[link=self, window=blank, width=100%]

. 各 VM 名の横にある矢印をクリックすると、各フェーズの進行状況が表示されます。
+
image::2025_summer/module-02-mtv/17_VM_Migration_Stages.png[link=self, window=blank, width=100%]

IMPORTANT: ラボ環境の制約や同時実行ユーザー数の影響で、実際の環境より転送速度が遅くなる場合があります。移行完了までそのままお待ちください。この間、他のセクションを先に進めることも可能です。移行された VM は後のモジュールで使用します。

[[interactive_demos]]
== 高度な機能のインタラクティブデモ

移行が完了するまでの間、MTV の高度な機能についてご紹介します。ここでは「自動設定フック」と「ウォームマイグレーション」のデモ動画を確認できます。

=== 自動設定フック (Automation Hooks)

フック機能は、移行プロセスの前後で VM の設定を自動変更できる非常に強力な機能です。

Ansible オートメーションを活用し、移行前（Pre-hook）や移行後（Post-hook）にプレイブックを実行します。別途 Ansible Automation Platform のサブスクリプションは不要で、*ansible-runner* ポッドが移行プロセスの中で自動的に実行されます。

.デモの内容：
* 移行前フック：ネットワークアダプターを VMware 形式から OpenShift の VirtIO 形式へ再構成。
* 移行後フック：不要になった設定のクリーンアップや、移行完了ログの記録。

=== ウォームマイグレーション

ダウンタイムを最小限に抑えたい重要なワークロードには、ウォームマイグレーションが適しています。

vSphere の Changed Block Tracking (CBT) 技術を利用し、VM を実行したまま初期コピーを行います。最終的な切り替え（カットオーバー）時にのみ短時間の停止が発生し、差分データのみを転送します。

.デモの内容：
* ウォームマイグレーション計画の作成と実行。
* カットオーバー（切り替え）操作の開始。
* 最小限の停止時間での移行完了を確認。

== まとめ

このセクションでは、MTV を使用した vSphere からの VM 移行手順を学習しました。Red Hat では、用途に応じて以下の移行ツールも提供しています：

* **Migration Toolkit for Applications (MTA)**: アプリのコンテナ化・モダナイゼーションを支援。
* **Migration Toolkit for Containers (MTC)**: OpenShift クラスター間での Pod 移行。

詳細は Red Hat の担当チームまでお問い合わせください。
