= 仮想マシンとアプリケーションの操作

== はじめに

このセクションでは、OpenShift Virtualization 環境における仮想マシンの「Day-2 運用（構築後の運用管理）」に焦点を当てます。これまでのラボで培った知識を活かし、特に VMware vSphere からインポートした 3 つの仮想マシンを操作して、ホストされているアプリケーションへのアクセス設定を行います。

具体的には、OpenShift の標準的なネットワーク公開手法である「Service」と「Route」を使用してアプリケーションを公開し、外部からアクセス可能にします。これにより、仮想マシン上のアプリケーションをコンテナネイティブな最新のアプローチで管理・提供する方法を学びます。

[[service_route]]
== Service と Route によるアプリケーションの公開

デフォルトで仮想マシンは SDN（ポッドネットワーク）に接続されており、他のネットワークリソースへ簡単にアクセスできます。しかし、クラスター内の他のポッドや外部クライアントが、特定の仮想マシンを自動的に検出して接続するのは難しい場合があります。

これを解決するために、*Service* を使用して 2 台の Windows Web サーバー間でトラフィックをロードバランシングし、DNS によるサービスディスカバリを有効にします。さらに、*Route* を作成して、クラスター外部のクライアントから仮想マシン内のアプリケーションへアクセスできるようにします。

IMPORTANT: 「既存の仮想マシンの移行」モジュールを完了していない場合は、先にそちらを実行することを強く推奨します。移行が未完了、または進行中の場合は、*vmimported-{user}* プロジェクトにあらかじめ用意されている VM を使用できます。その場合は、以下の手順内の *vmexamples-{user}* を *vmimported-{user}* に読み替えて進めてください。

=== サービスの概要

*Service* は、ラベルに基づいて接続先（エンドポイント）を識別し、クライアントからのトラフィックを適切にルーティングします。現在の VM にはまだ識別用のラベルが付与されていないため、以下の手順で設定を行います。

* VM に共通のラベルを追加します（2 台の Windows IIS サーバーを同じロードバランサーに紐付けるため）。
* Service を作成します。OpenShift は Service 名を DNS 名として登録し、クラスター内部からロードバランサーとしてアクセス可能にします。
* *Route* を作成し、OpenShift の外部からこの Service を利用可能にします。

=== 仮想マシンへのラベル付与

. 左メニューの *VirtualMachines* をクリックします。インポートした 3 つの VM が停止している場合は、*Start（開始）* をクリックして起動してください。右側の *Status* 列でソートすると確認がスムーズです。
+
image::2025_spring/module-08-workingvms/11_Import_VMs_List.png[link=self, window=blank, width=100%]
+
NOTE: 作業中のプロジェクト（*vmexamples-{user}* または *vmimported-{user}*）が正しく選択されているか確認してください。

. *winweb01-{user}* を選択し、*YAML* タブに移動します。
. `spec:` セクション内の `template.metadata.labels` セクションに以下のラベルを追加します。
+
[source,yaml,role=execute]
----
env: webapp
----
+
IMPORTANT: インデント（字下げ）がずれないよう、以下のスクリーンショットを参考に正確に入力してください。
+
image::2025_spring/module-08-workingvms/12_Imported_VMs_YAML.png[link=self, window=blank, width=100%]

. *winweb02-{user}* に対しても、同様のラベル追加を**繰り返します**。
. ラベル設定後、*winweb01-{user}* と *winweb02-{user}* の両方の VM を再起動してください。
+
NOTE: 再起動後、*Console* タブから VM が正常に起動していることを確認してください。

=== サービスの作成

. 左メニューの *Networking* を展開し、*Services* をクリックします。画面右上の *Create Service* ボタンをクリックします。
+
image::2025_spring/module-08-workingvms/13_Navigate_Service.png[link=self, window=blank, width=100%]

. 表示された YAML テンプレートを、以下の定義に置き換えます。
+
[source,yaml,role=execute,subs="attributes"]
----
apiVersion: v1
kind: Service
metadata:
  name: webapp
  namespace: vmexamples-{user}
spec:
  selector:
    env: webapp
  ports:
  - protocol: TCP
    port: 80
    targetPort: 80
----
+
IMPORTANT: `namespace` の値が、実際に VM が存在するプロジェクト名（*vmexamples-{user}* または *vmimported-{user}*）と一致していることを必ず確認してください。
+
image::2025_spring/module-08-workingvms/14_Service_YAML.png[link=self, window=blank, width=100%]

. 画面下部の *Create* をクリックします。保存完了の通知が表示されます。
. 作成した *webapp* サービスの詳細ページで、*Pod selector* のリンクをクリックします。
+
image::2025_spring/module-08-workingvms/15_Imported_VMs_PodSelector.png[link=self, window=blank, width=100%]

. 2 台の Windows VM が、サービスによって正しく識別・ターゲットされていることを確認します。
+
image::2025_spring/module-08-workingvms/16_Imported_VMs_Pods.png[link=self, window=blank, width=100%]

=== ルートの作成

これで、Windows IIS サーバーは OpenShift クラスター内部からアクセス可能になりました（DNS 名: `webapp.vmexamples-{user}.svc.cluster.local`）。次に、これをアプリケーションのフロントエンドとして外部へ公開するために *Route* を作成します。

. 左メニューの *Networking* > *Routes* をクリックし、*Create Route* をクリックします。
+
image::2025_spring/module-08-workingvms/17_Route_Navigation.png[link=self, window=blank, width=100%]

. 以下の情報を入力し、最下部の *Create* をクリックします。
.. *Name*: *route-webapp*
.. *Service*: *webapp*
.. *Target port*: *80 -> 80 (TCP)*
.. *Secure Route*: チェックを入れる（Enabled）
.. *TLS termination*: *Edge*
.. *Insecure traffic*: *Redirect*
+
image::2025_spring/module-08-workingvms/18_Create_Route.png[link=self, window=blank, width=100%]

. 作成後、詳細画面の *Location* フィールドに表示されている URL にアクセスします。
+
image::2025_spring/module-08-workingvms/19_Route_Access.png[link=self, window=blank, width=100%]

. おそらく、ページを開くとエラーが表示されるはずです。これは、移行した Web サーバーがデータベース VM と通信できていないことが原因です。
+
image::2025_spring/module-08-workingvms/20_WebApp_Error.png[link=self, window=blank, width=100%]
+
NOTE: この問題を解決するには、データベース VM 用の Service も作成し、Web サーバーから DNS 名で名前解決できるようにする必要があります。

. 再度、*Networking* > *Services* > *Create Service* を開き、YAML を以下に置き換えて作成します。
+
[source,yaml,role=execute,subs="attributes"]
----
apiVersion: v1
kind: Service
metadata:
  name: database
  namespace: vmexamples-{user}
spec:
  selector:
    vm.kubevirt.io/name: database-{user}
  ports:
  - protocol: TCP
    port: 3306
    targetPort: 3306
----
+
IMPORTANT: `namespace` が正しいことを確認してください。

. *Create* ボタンをクリックして保存します。
. ブラウザに戻り、先ほどの URL（webapp）をリロードしてください。移行した Web アプリケーションが正常にデータベースと接続され、画面が表示されるはずです。
+
image::2025_spring/module-08-workingvms/22_WebApp_Success.png[link=self, window=blank, width=100%]

== まとめ

このモジュールでは、移行した仮想マシンに対して OpenShift ネイティブの Service と Route 機能を適用しました。これにより、仮想化環境においてもコンテナと同様の最新のアプローチでネットワーク公開とロードバランシングを実現できることを学びました。
