== はじめに
Azure Red Hat OpenShift（ARO）上のRed Hat OpenShift Virtualizationは、従来の仮想化プラットフォームからモダンなクラウドネイティブアプリケーションインフラストラクチャへの移行を検討する組織にとって、明確で実践的なパスを提供します。
仮想マシン（VM）をKubernetesベースの基盤に移行することで、チームは既存のワークロードを信頼を持って移行でき、同時に長期的な近代化とイノベーションの段階を整えることができます。

Red HatとMicrosoftが共同で開発したOpenShift Virtualization on AROは、仮想マシン、コンテナ、サーバーレスワークロードの管理を単一の一貫したエクスペリエンスの下で統合する、セキュアでエンタープライズグレードのプラットフォームを提供します。
Migration Toolkit for Virtualization（MTV）やAnsible Automation Platform（AAP）などの統合ツールを使用することで、管理者は移行を効率化し、継続的な運用を自動化し、ハイブリッドおよびマルチクラウド環境全体の複雑さを軽減できます。

Azure Red Hat OpenShift上で実行されるOpenShift Virtualizationは、これらの機能をマネージドサービス、自動化されたDay 2運用、継続的な更新で拡張し、Red HatのオープンソースイノベーションとRHELの専門知識をMicrosoftのクラウド信頼性とスケール性と組み合わせています。
その結果、柔軟で安全性が高く、将来対応のプラットフォームが実現され、運用オーバーヘッドが削減され、組織は自らのペースで近代化を進めることができます。

このワークショップは、Azure Red Hat OpenShift上のRed Hat OpenShift Virtualizationへの実践的な入門を提供します。
VM作成、移行、自動化、ライフサイクル管理など、一般的な管理業務と運用タスクを、本番環境で使用されているのと同じツールとワークフローを使用して探索します。
ラボの終了までに、OpenShift Virtualization on AROがVM管理をいかに簡素化し、プラットフォーム効率を向上させ、ハイブリッドクラウド近代化の基盤を提供するかを理解できるようになります。

== ロードショーに参加すると最も利益を得られるのは誰ですか？

*仮想マシン管理者* -- OpenShift Virtualizationの仮想マシンの日常管理を担当する者。これらのユーザーは、仮想マシンのプロビジョニングや日常管理、およびその内部で実行されているアプリケーションの管理に責任を持つことがよくあります。

*仮想インフラストラクチャ管理者* -- OpenShift Virtualizationソリューションをホストしている物理インフラストラクチャの責任者。これらのユーザーは、物理ハードウェア、ストレージ、ネットワーク変更に責任を持ち、実行中の仮想マシンの日常運用に影響を与えます。

== ロードショーで扱われるコンテンツは何ですか？

以下が扱われる*7つ*の主要セクションです：

* _仮想マシン管理_: このセクションでは、仮想マシンの作成やリソース割り当ての変更を含む、仮想マシン管理の基礎をレビューします。

* _既存の仮想マシンの移行_: このセクションでは、Migration Toolkit for Virtualization（MTV）を使用して、既存のVMware vSphere環境からOpenShift Virtualizationへ仮想マシンを移行します。

* _ストレージ管理_: OpenShift Virtualizationに関連する多くのストレージ管理アクションについて、多くの管理者に馴染みのあるストレージパラダイムがどのように変わるかを探索します。

* _仮想マシンのバックアップとリカバリー_: このユニットでは、VMを外部サイトにバックアップし、災害時にリストアするための追加の概念を紹介および実演します。

* _テンプレートとInstanceType管理_: 仮想マシンのデプロイを効率化するために、管理者はテンプレートを作成またはInstanceTypeを定義することがよくあります。このセクションではそれらのプロセスに焦点を当てます。

* _仮想マシンとアプリケーションの操作_: このセクションでは、インポートした仮想マシンでいくつかのday-2アクティビティを実行し、VM上のアプリケーションをサービスとルート経由で公開します。

* _ネットワーク管理_: デフォルトでは、VMはOpenShiftのポッドネットワークに接続されています。このセクションでは、新しいL2ネットワークマッピングの作成と、直接ネットワーク接続のためのユーザー定義ネットワーク（UDN）の使用について探索します。

== OpenShift Virtualizationとは何ですか？

* すべての現在のサブスクライバーは、OpenShift Subscriptionの一部としてOpenShift Virtualizationを受け取ります。
OpenShift 4.5がリリースされた時からOpenShift 4.18でAzure Red Hat Openshiftで正式にリリースされています。
* OpenShift Virtualizationは、Cloud Native Computing Foundation（CNCF）のインキュベーションプロジェクトであるKubeVirtプロジェクトの下流で開発されている「コンテナネイティブ仮想化」技術に基づいています。
* Red Hat Enterprise Linux KVM ハイパーバイザー（RHEL KVM）を活用します。これは多くの組織とクラウドサービスプロバイダーによってグローバルに使用されている成熟した高性能なオープンソースハイパーバイザーで、15年以上開発されています。
* OpenShift VirtualizationはRHEL KVMハイパーバイザーを活用し、VMをKubernetesとKubeVirtで管理することを可能にします。
OpenShift Virtualization VMはKubernetesスケジューリング、ネットワーク、ストレージインフラストラクチャを使用します。

* OpenShift VirtualizationはMicrosoftのWindows ゲストサポート向けにSVVP認定されており、Red Hatの他のKVM仮想化オファリングに適用されるのと同じルールに従っています。
* Azure上のOpenshift Virtualizationは、Boost インスタンスタイプでサポートされています。
サポートされているインスタンスの完全なリストについては、https://learn.microsoft.com/en-us/azure/openshift/howto-create-openshift-virtualization[サポートページ]を参照してください。
* OpenShift Virtualizationにより、OpenShiftはテストを展開、管理し、仮想マシンをOpenShiftクラスタ内のリソースに接続できます。
これには、Kubernetes ネイティブメソッドを使用してそれらのVMに接続して管理し、パイプライン、GitOps、Service Mesh などのOpenShift機能を利用する機能が含まれます。

== 従来のVMプラットフォームから切り替える理由は何ですか？

**クラウドネイティブ開発またはクラウドネイティブ運用の採用：**
Azure Red Hat OpenShiftは、チームがスピード、俊敏性、確信、選択肢を持ってアプリケーションを構築するのに役立ちます。
どこを選んでも本番環境でコーディングします。
重要な仕事に戻してください。

**完全なアプリ開発スタック：**
Red Hat OpenShift Dev Spaces（以前のRed Hat CodeReady Workspaces）、ランタイム、統合とプロセスオートメーション、サーバーレス、パイプライン、その他セキュリティを備えたものが含まれます。

**インフラストラクチャ支出をイノベーションにシフト：**
OpenShift ネイティブアーキテクチャにより、重い機能の費用構造がSDDCレガシーから軽量なコンテナネイティブフレームワークに変わります。

**リスク軽減：**
OpenShiftはオンプレミスとパブリッククラウドの両方のオプションをサポートしているため、OpenShiftはパブリッククラウドロックインに対する保険です。

**インフラストラクチャから独立：**
Red Hat OpenShiftはベアメタル、オンプレミス仮想化、またはパブリッククラウドで一貫して実行され、デプロイと更新の究極の選択肢と柔軟性を提供します。

**純粋なオープンソースイノベーション：**
Kubernetes、サーバーレス、サービスメッシュ、Kubernetes Operators、その他のイノベーションは、Red Hatが主導するオープンソースの速度によって推進されています。
