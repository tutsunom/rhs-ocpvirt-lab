= 仮想マシンのネットワーク管理

== はじめに

前のセクションで説明したように、すべての仮想マシンはデフォルトで OpenShift ソフトウェア定義ネットワーク（SDN）に接続されています。これにより、他の VM やコンテナアプリケーションからのアクセスが可能になり、仮想マシンをコンテナと同様の現代的なワークフローで管理できるようになります。

* SDN は、VM やポッドに関わらず、アプリケーションの抽象化、接続、制御された公開（Service や Route など）といった高度な機能を提供します。
* OpenShift のネットワークポリシーにより、特定の VM やプロジェクト単位でトラフィックの許可・拒否ルールを柔軟に作成できます。

一方で、必要に応じて仮想マシンを物理ネットワーク（VLAN など）に直接接続することも可能です。これにより、外部ネットワークの IP アドレスから VM に直接通信したり、レイヤー 2 ネットワークで既存のインフラと連携したりできます。

本セクションでは、Linux ブリッジなどのホストネットワーク設定を確認し、仮想マシンを物理ネットワークに接続するための「ネットワークアタッチメント定義（NAD）」の作成手順を解説します。

NOTE: OpenShift 環境では、仮想マシンが動作する各コンピュートノード上に、外部ネットワーク接続用の Linux ブリッジがあらかじめ設定されています。

+

+
image::2025_spring/module-09-networking/02_NodeNetworkState_Info.png[link=self, window=blank, width=100%]

. 詳細を閉じます。この **br-flat** というブリッジは *Kubernetes NMState Operator* によって作成されたものです。左メニューの *NodeNetworkConfigurationPolicy* をクリックすると、そのポリシーを確認できます。
+
image::2025_spring/module-09-networking/03_NodeNetworkConfigurationPolicy_List.png[link=self, window=blank, width=100%]

. **br-flat** を選択して情報を取得します。
+
image::2025_spring/module-09-networking/04_NodeNetworkConfigurationPolicy_Info.png[link=self, window=blank, width=100%]

NOTE: *NodeNetworkConfigurationPolicy* はノードレベルの設定であるため、一般ユーザー権限では変更できません。

. **YAML** タブに切り替えると、このブリッジがどのように定義されているかを確認できます。管理者権限があれば、同様の YAML を使用して独自のブリッジを作成可能です。
+
image::2025_spring/module-09-networking/05_NodeNetworkConfigurationPolicy_YAML.png[link=self, window=blank, width=100%]


////
[source,yaml]
----
apiVersion: nmstate.io/v1
kind: NodeNetworkConfigurationPolicy
metadata:
  name: br-flat
spec:
  desiredState:
    interfaces:
      - bridge:
          options:
            stp:
              enabled: false
          port:
            - name: enp3s0
        description: Linux bridge with enp3s0 as a port
        ipv4:
          dhcp: false
          enabled: false
        name: br-flat
        state: up
        type: linux-bridge
----
////

== ネットワークアタッチメント定義（NAD）の作成

仮想マシンで Linux ブリッジを利用するには、**ネットワークアタッチメント定義（NAD）** を作成する必要があります。これは OpenShift に対し、「物理デバイス（br-flat）を仮想マシンが利用できるネットワークとして登録する」ことを通知するものです。

NAD はプロジェクト（名前空間）スコープのリソースであり、作成したプロジェクト内の VM のみがアクセスできます（*default* プロジェクトで作成した場合はグローバルに利用可能です）。

NOTE: NAD は既存のネットワークデバイス（今回は **br-flat**）を利用するように OpenShift に指示します。デバイス名が一致していないと、VM をノードに配置できないため注意してください。

. 左メニューから *Network* > *Network Attachment Definitions* を選択し、*Create network attachment definition* をクリックします。
+
image::2025_spring/module-09-networking/06_NetworkAttachDefinition_Create.png[link=self, window=blank, width=100%]
+
IMPORTANT: NAD を作成する際は、必ず **vmexamples-{user}** プロジェクトを選択していることを確認してください。

. 以下の情報を入力し、*Create* をクリックします。
* *Name*: flatnetwork
* *Network Type*: Linux bridge
* *Bridge Name*: **br-flat**
+
image::2025_summer/module-09-networking/07_NetworkAttachDefinition_Create_Form.png[link=self, window=blank, width=100%]
+
NOTE: 今回はタグなし（Untagged）ネットワークを使用するため、*VLAN Tag Number* は空欄のままで構いません。

. NAD が正常に作成されたことを確認します。
+
image::2025_summer/module-09-networking/08_NetworkAttachDefinition_Created.png[link=self, window=blank, width=100%]

== ユーザー定義ネットワーク（User Defined Networks: UDN）

OpenShift 4.17 から導入された **ユーザー定義ネットワーク（UDN）** は、プロジェクトごとに完全に分離されたレイヤー 2 またはレイヤー 3 のネットワークセグメントを、デフォルトの OVN-Kubernetes CNI を通じて提供します。

従来の仮想化管理者が慣れ親しんだ「テナントごとのネットワーク分離」を実現しつつ、複雑なネットワークポリシーを設定することなく、高いセキュリティと柔軟性を確保できます。

UDN の主な利点:
* **強力な分離**: 名前空間ごとにプライマリネットワークを分離し、テナント間のセキュリティを向上。
* **柔軟なトポロジー**: プライマリネットワークとしてレイヤー 2 またはレイヤー 3 を選択可能。
* **IP アドレスの保持**: レイヤー 2 トポロジーにより、ライブマイグレーション中も VM の IP アドレスが維持されます。

=== UDN の操作

事前に、UDN 用の名前空間 **vmexamples-{user}-udn** が用意されています。

. *Networking* > *UserDefinedNetworks* に移動し、プロジェクトに **vmexamples-{user}-udn** を選択します。
+
image::2025_spring/module-09-networking/14_UDN_List.png[link=self, window=blank, width=100%]

. *Create* > *UserDefinedNetwork* を選択します。
. サブネットに **192.168.254.0/24** を指定して *Create* をクリックします。
+
image::2025_spring/module-09-networking/16_UDN_Form.png[link=self, window=blank, width=100%]

. 作成された UDN を確認します。デフォルト名は **primary-udn** になります。
+
image::2025_spring/module-09-networking/17_UDN_Created.png[link=self, window=blank, width=100%]

. 仮想マシンの作成: UDN に接続する VM を作成するため、以下の YAML 定義をインポートします。
+
image::2025_spring/module-09-networking/19_UDN_Import_YAML.png[link=self, window=blank, width=100%]
+
[source,yaml,role=execute,subs="attributes"]
----
apiVersion: kubevirt.io/v1
kind: VirtualMachine
metadata:
  labels:
    kubevirt.io/vm: fedora-udn
  name: fedora-udn
  namespace: vmexamples-{user}-udn
spec:
  dataVolumeTemplates:
    - apiVersion: cdi.kubevirt.io/v1beta1
      kind: DataVolume
      metadata:
        creationTimestamp: null
        name: fedora-udn
      spec:
        sourceRef:
          kind: DataSource
          name: fedora
          namespace: openshift-virtualization-os-images
        storage:
          resources:
            requests:
              storage: 30Gi
  runStrategy: Always
  template:
    metadata:
      name: fedora-udn
      namespace: vmexamples-{user}-udn
    spec:
      domain:
        devices:
          disks:
          - disk:
              bus: virtio
            name: rootdisk
          - disk:
              bus: virtio
            name: cloudinitdisk
          interfaces:
          - name: primary-udn
            binding:
              name: l2bridge
          rng: {}
        resources:
          requests:
            memory: 2048M
      networks:
      - pod: {}
        name: primary-udn
      terminationGracePeriodSeconds: 0
      volumes:
      - dataVolume:
          name: fedora-udn
        name: rootdisk
      - cloudInitNoCloud:
          userData: |-
            #cloud-config
            user: fedora
            password: fedora
            chpasswd: { expire: False }
        name: cloudinitdisk
----

. **Create** をクリックして VM を作成します。起動後、**Overview** タブの *Network* タイルで、UDN から割り当てられた IP（192.168.254.x）が表示されていることを確認してください。
+
image::2025_spring/module-09-networking/21_UDN_Network_Tile.png[link=self, window=blank, width=100%]
. [Console]タブに切り替えて、提供されたゲスト認証情報を使用してVMにログインします。
+
image::2025_spring/module-09-networking/22_UDN_Fedora_Console.png[link=self, window=blank, width=100%]
+
.. VMは定義されたサブネットからIPが割り当てられます。
.. VMはDHCPからゲートウェイ設定を自動的に取得します。
.. VMはユーザー定義ネットワークを使用してインターネットにアクセスできます。
== まとめ

このモジュールでは、仮想マシンを外部ネットワークに直接接続する Linux ブリッジ設定と、最新のユーザー定義ネットワーク（UDN）による高度な分離について学びました。これにより、要件に応じて従来の物理インフラとの連携と、クラウドネイティブなセルフサービスネットワークを使い分けることが可能になります。

ユーザー定義ネットワークは、クラスタ管理者とエンドユーザーに高度にカスタマイズ可能なネットワーク設定オプションと、プライマリとセカンダリネットワークタイプの両方を管理する方がはるかに柔軟な経験を提供します。
