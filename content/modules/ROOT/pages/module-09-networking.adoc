=  仮想マシンのネットワーク管理

== はじめに

前のセクションで説明したように、すべての仮想マシンはデフォルトでOpenShiftソフトウェア定義ネットワーク（SDN）に接続されており、これにより、他のOpenShiftクラスタ上のワークロード（他のVM、OpenShiftネイティブアプリケーションを含む）からのアクセスが可能になり、仮想マシンとそれらがホストするアプリケーションをより現代的なワークフローで管理できるようになります。

* SDNは、クラスタに展開されているVM、ポッド、その他のアプリケーションに関わらず、アプリケーションの抽象化、接続、および制御された方法での公開に関する追加機能を提供します。これらにはOpenShiftの*Service*および*Route*機能が含まれます。
* OpenShiftのネットワークポリシーエンジンにより、VM ユーザーまたは管理者は、個別のVMまたはプロジェクト/名前空間全体との間のネットワークトラフィックを許可または拒否するルールを作成できます。

ただし、必要に応じて、仮想マシンがタグなしネットワークやVLANなどの1つ以上の物理ネットワークに直接接続することも可能です。これはSDNに加えて機能するため、たとえば、管理者は外部IPアドレスからVMに接続でき、VMはレイヤー2ネットワークを使用して直接接続できます。

大まかには、Linuxブリッジなどのホストネットワーキングを設定することで行われます。このワークショップのセグメントでは、ネットワークアタッチメント定義を作成してVMがそのブリッジに接続でき、したがって直接物理ネットワークに接続できるようにするプロセスの次のステップを説明します。

NOTE: OpenShift環境は、仮想マシンが接続する各コンピュートノード上にLinuxブリッジが既に設定されており、外部ネットワークリソースとの接続が容易になっています。

== ネットワークアタッチメント定義の作成

VMでLinuxブリッジを使用するには、*ネットワークアタッチメント定義*を作成する必要があります。これはOpenShiftにネットワークについて通知し、仮想マシンがそれに接続できるようにします。ネットワークアタッチメント定義はプロジェクトスコープであり、それが作成されたプロジェクトに対してのみであり、そのプロジェクトに展開されている仮想マシンのみがアクセスできます。*default*プロジェクトでネットワークアタッチメント定義が作成された場合、それはグローバルに利用可能になります。これにより、管理者は、特定のユーザーが自分のVMを管理するためにアクセスできるや利用できないネットワークを制御できます。

NOTE: ネットワークアタッチメント定義は、既存のネットワークデバイスをOpenShiftが利用するように指示します。この場合のデバイスは以前に作成され、*br-flat*という名前です。その名前を使用する必要があります。そうしないと、OpenShiftがVMをコンピュートノードに配置できません。特別に名前が付けられたネットワークデバイスがあるノードのみを利用できるためです。

. 左側のメニューから*Network*を選択し、次に*Network Attachment Definitions*を選択して、*Create network attachment definition*ボタンをクリックします。
+
image::2025_spring/module-09-networking/06_NetworkAttachDefinition_Create.png[link=self, window=blank, width=100%]
+

IMPORTANT: ネットワークアタッチメント定義を作成するときは、vmexamples-{user}プロジェクトにいることを確認してください。

. *vmexamples-{user}*プロジェクトのフォームを次のように完成させて、*Create network attachment definition*をクリックします:

== ユーザー定義ネットワーク

ユーザー定義ネットワーク（UDN）の実装前、OpenShift Container Platform用のOVN-Kubernetes CNIプラグインはプライマリまたはメインネットワーク上のレイヤー3トポロジのみをサポートしていました。Kubernetesの設計原則に従って、すべてのポッドはメインネットワークに接続され、すべてのポッド通信はIPアドレスで行われ、ポッド間トラフィックはネットワークポリシーに従って制限されます。新しいネットワークアーキテクチャを学ぶことは、従来の仮想化管理者から多くの懸念点として表現されています。

UDNの導入により、カスタムレイヤー2、レイヤー3、およびローカルネットネットワークセグメントを有効にすることで、デフォルトレイヤー3トポロジの柔軟性とセグメンテーション機能が向上し、これらのセグメントはすべてデフォルトで分離されています。これらのセグメントは、デフォルトのOVN-Kubernetes CNIプラグインを使用するコンテナポッドと仮想マシンのプライマリまたはセカンダリネットワークとして機能します。UDNは幅広いネットワークアーキテクチャとトポロジを有効にし、ネットワークの柔軟性、セキュリティ、パフォーマンスを向上させます。

クラスタ管理者は、UDNを使用して、ClusterUserDefinedNetworkカスタムリソース（CR）を活用することで、複数の名前空間にまたがるクラスタレベルの追加ネットワークを作成および定義できます。さらに、クラスタ管理者またはクラスタユーザーは、UDNを使用して、UserDefinedNetwork CRを使用して名前空間レベルで追加ネットワークを定義できます。

ユーザー定義ネットワークには、次の利点があります:

*セキュリティのための強化されたネットワーク分離* -  名前空間は、Red Hat OpenStack Platform（RHOSP）でテナントが分離されるのと同じように、独自の分離されたプライマリネットワークを持つことができます。これはクロステナントトラフィックのリスクを軽減することで、セキュリティを向上させます。

*ネットワークの柔軟性* - クラスタ管理者は、プライマリネットワークをレイヤー2またはレイヤー3ネットワークタイプとして設定できます。これにより、プライマリネットワークへのセカンダリネットワークの柔軟性が提供されます。

*ネットワーク管理の簡素化* -  ユーザー定義ネットワークにより、分離は異なるネットワークにワークロードをグループ化することで実現できるため、複雑なネットワークポリシーの必要性が排除されます。

*高度な機能* - ユーザー定義ネットワーク機能により、管理者は複数の名前空間を単一ネットワークに接続したり、異なるセットの名前空間用に異なるネットワークを作成したりできます。ユーザーは、異なる名前空間とクラスタ間でIPサブネットを指定して再利用することもでき、一貫性のあるネットワーク環境を提供します。


=== OpenShift仮想化でのユーザー定義ネットワーク

OpenShift Container Platform Webコンソールまたはコマンドラインインターフェース（CLI）を使用して、仮想マシン（VM）をVMのプライマリインターフェース上のユーザー定義ネットワーク（UDN）に接続できます。プライマリユーザー定義ネットワークは、指定された名前空間内のデフォルトポッドネットワークを置き換えます。ポッドネットワークとは異なり、プロジェクトごとにプライマリUDNを定義でき、各プロジェクトは特定のサブネットとトポロジを使用できます。

レイヤー2トポロジでは、OVN-Kubernetesはノード間にオーバーレイネットワークを作成します。このオーバーレイネットワークを使用して、異なるノード上のVMに接続でき、物理ネットワークインフラストラクチャを追加で設定する必要はありません。

レイヤー2トポロジにより、ライブマイグレーション中にクラスタノード全体で永続的なIPアドレスが保持されるため、ネットワークアドレス変換（NAT）の必要なしにVMをシームレスに移行できます。

プライマリUDNを実装する前に、次の制限事項を考慮する必要があります:

. virtctl sshコマンドを使用してVMへのSSHアクセスを設定することはできません。

. oコマンドport-forwardコマンドを使用してVMにポートを転送することはできません。

. ヘッドレスサービスを使用してVMにアクセスすることはできません。

. 準備状態プローブとライブネスプローブを定義してVM健全性チェックを設定することはできません。

NOTE: OpenShift仮想化は現在、セカンダリユーザー定義ネットワークをサポートしていません。

=== ユーザー定義ネットワークの操作

UDNにアクセスできるポッドを作成する前に、名前空間とネットワークを作成する必要があります。新しいネットワークにポッドを持つ名前空間を割り当てるか、既存の名前空間にUDNを作成すると、OVN-Kubernetesによって受け入れられません。

このタスクはクラスタ管理者が実行する必要があります。適切なラベル（*k8s.ovn.org/primary-user-defined-network*）を含む*vmexamples-{user}-udn*という名前空間を割り当てました。

+
image::2025_spring/module-09-networking/15_UDN_Create.png[link=self, window=blank, width=100%]

* デフォルトはレイヤー2です（OpenShift仮想化で現在サポートされている唯一のレイヤー）。
* ロールはプライマリです（仮想マシンは現在のところプライマリネットワークのみを使用できます）。

. UserDefinedNetworkに接続された仮想マシンを作成するには、YAML定義のいくつかの https://docs.redhat.com/en/documentation/openshift_container_platform/4.18/html/virtualization/networking#virt-connecting-vm-to-primary-udn[調整が必要です^]。このラボで作業を簡単にするために、次のYAML定義を使用してUserDefinedNetworkに接続された全体のVMを定義するだけです:

. 次の画像に示すように、トップメニューを使用してYAMLをインポートできます:
+
image::2025_spring/module-09-networking/19_UDN_Import_YAML.png[link=self, window=blank, width=100%]
+
[source,yaml,role=execute,subs="attributes"]
----
apiVersion: kubevirt.io/v1
kind: VirtualMachine
metadata:
  labels:
    kubevirt.io/vm: fedora-udn
  name: fedora-udn
  namespace: vmexamples-{user}-udn
spec:
  dataVolumeTemplates:
    - apiVersion: cdi.kubevirt.io/v1beta1
      kind: DataVolume
      metadata:
        creationTimestamp: null
        name: fedora-udn
      spec:
        sourceRef:
          kind: DataSource
          name: fedora
          namespace: openshift-virtualization-os-images
        storage:
          resources:
            requests:
              storage: 30Gi
  runStrategy: Always
  template:
    metadata:
      name: fedora-udn
      namespace: vmexamples-{user}-udn
    spec:
      domain:
        devices:
          disks:
          - disk:
              bus: virtio
            name: rootdisk
          - disk:
              bus: virtio
            name: cloudinitdisk
          interfaces:
          - name: primary-udn
            binding:
              name: l2bridge
          rng: {}
        resources:
          requests:
            memory: 2048M
      networks:
      - pod: {}
        name: primary-udn
      terminationGracePeriodSeconds: 0
      volumes:
      - dataVolume:
          name: fedora-udn
        name: rootdisk
      - cloudInitNoCloud:
          userData: |-
            #cloud-config
            user: fedora
            password: fedora
            chpasswd: { expire: False }
        name: cloudinitdisk
----

== まとめ

このモジュールでは、物理ネットワークを操作し、仮想マシン（VM）を既存ネットワークに直結接続することを確認しました。VMを物理ネットワークに直列に接続することで、管理者はVMに直接アクセスでき、同時にVMをストレージや管理ネットワークなどの特別なネットワークに接続できます。

ユーザー定義ネットワークは、クラスタ管理者とエンドユーザーに高度にカスタマイズ可能なネットワーク設定オプションと、プライマリとセカンダリネットワークタイプの両方を管理する方がはるかに柔軟な経験を提供します。
