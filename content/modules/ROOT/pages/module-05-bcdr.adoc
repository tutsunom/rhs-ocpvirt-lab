= 仮想マシンのバックアップとリカバリ

== はじめに

エンタープライズワークロードにおいてデータ保護は極めて重要なトピックであり、OpenShift Virtualization を使用した VM のバックアップとリカバリには豊富なオプションが用意されています。これらのソリューションの多くは、OpenShift の Pod を保護する手法と同様に機能します。具体的には、VM 単体、あるいは複数の VM を含むプロジェクト（ネームスペース）全体のバックアップを取得し、リモートのオブジェクトストレージバケットへ保存します。バックアップには、VM の定義（メタデータやカスタムリソース）とともに、永続ストレージボリューム（PV）のデータも含まれます。

Red Hat の提供ソリューション：

* https://docs.redhat.com/en/documentation/openshift_container_platform/4.18/html/backup_and_restore/oadp-application-backup-and-restore[*OpenShift APIs for Data Protection (OADP)*^]：OpenShift オブジェクト（VM を含む）のバックアップとリストアのための、ストレージに依存しない標準的な手法を提供する Red Hat オペレーターです。
* https://docs.redhat.com/en/documentation/red_hat_openshift_data_foundation/4.18/html/configuring_openshift_data_foundation_disaster_recovery_for_openshift_workloads/metro-dr-solution[*OpenShift Data Foundation Metro-DR*^] および https://docs.redhat.com/en/documentation/red_hat_openshift_data_foundation/4.18/html/configuring_openshift_data_foundation_disaster_recovery_for_openshift_workloads/rdr-solution[*OpenShift Data Foundation Regional-DR*^]

エコシステムパートナーのソリューション：

* https://www.cohesity.com/press/cohesity-enhances-data-protection-and-cyber-resilience-for-red-hat-openshift-virtualization-workloads/[*Cohesity DataProtect*^]
* https://docs.netapp.com/us-en/trident/index.html[*NetApp Trident Protect*^]
* https://portworx.com/blog/disaster-recovery-for-red-hat-openshift-virtualization/[*Portworx Disaster Recovery for OpenShift Virtualization*^]
* https://www.rubrik.com/solutions/openshift[*Rubrik for OpenShift*^]
* https://storware.eu/solutions/virtual-machine-backup-and-recovery/openshift-virtualization-and-kubevirt/[*Storware Backup and Recovery*^]
* https://docs.trilio.io/kubernetes/appendix/backup-and-restore-virtual-machine-running-on-openshift-virtualization[*Trilio for Kubernetes*^]
* https://docs.kasten.io/latest/usage/openshift_virtualization.html[*VEEAM Kasten*^]

NOTE: このリストはすべてを網羅しているわけではありません。OpenShift Virtualization との互換性については、各ストレージまたはデータ保護ベンダーに確認するか、**https://catalog.redhat.com/platform/red-hat-openshift/virtualization#virtualization-infrastructure[Red Hat EcoSystem Catalog^]** を参照してください。

このラボでは、OADP を使用して仮想マシンのバックアップとリストア操作を実行します。

[[review_operator]]
== OADP オペレーターの確認

. パースペクティブを *管理者 (Administrator)* に切り替え、左メニューの *Operators* -> *Installed Operators* を選択します。プロジェクト（ネームスペース）が *oadp-{user}* になっていることを確認してください。
+
image::2025_summer/module-05-bcdr/00_Left_Menu.png[link=self, window=blank, width=100%]

. 一覧から OADP オペレーターをクリックして詳細を表示します。

. 利用可能な *Provided APIs* を確認します。このモジュールでは、*Backup*（バックアップ）と *Restore*（リストア）機能を使用します。
+
image::2025_summer/module-05-bcdr/01_Overview.png[link=self, window=blank, width=100%]

. 上部のタブバーから *DataProtectionApplication* タブを選択します。このオブジェクトは、デプロイされた OADP インスタンスの構成を定義しています。
+
image::2025_summer/module-05-bcdr/02_DPA.png[link=self, window=blank, width=100%]

. *oadp-dpa* をクリックして詳細画面を開き、上部の *YAML* タブで構成内容を確認します。
+
image::2025_spring/module-05-bcdr/03_OADP_YAML.png[link=self, window=blank, width=100%]
+
構成内で `kubevirt` プラグインが有効化されており、OpenShift Data Foundation (ODF) が提供する内部オブジェクトストレージバケットを保存先として使用するように設定されている点に注目してください。
+
IMPORTANT: ラボの便宜上、バックアップ先にはローカルのオブジェクトバケットを使用していますが、本番環境では災害対策として、外部のストレージシステムやクラウドベースのオブジェクトストレージを選択することを推奨します。

[[create_backup]]
== 仮想マシンのバックアップ作成

前のセクションで作成した VM *fedora02* のバックアップを実行します。バックアップ対象はラベル `app` および `vm.kubevirt.io/name` によって識別されます。これには VM 本体の定義、ディスク、および ConfigMap や Secret などの関連オブジェクトがすべて含まれます。

NOTE: 前のセクションを完了していない、または *fedora02* が存在しない場合は、以下の YAML 内のラベルセレクターを実際の VM と一致するように適宜変更してください。

. オペレーターの詳細画面に戻り、上部タブから *Backup* を選択します。

. *Create Backup* ボタンをクリックします。
+
image::2025_summer/module-05-bcdr/04_Backup_Tab.png[link=self, window=blank, width=100%]

. *YAML view* に切り替え、既存の内容を以下の定義に置き換えます：
+
[source,yaml,role=execute,subs="attributes"]
----
---
apiVersion: velero.io/v1
kind: Backup
metadata:
  name: backup-fedora02
  namespace: oadp-{user}
  labels:
    velero.io/storage-location: default
spec:
  defaultVolumesToFsBackup: false
  orLabelSelectors:
  - matchLabels:
      app: fedora02
  - matchLabels:
      vm.kubevirt.io/name: fedora02
  csiSnapshotTimeout: 10m0s
  ttl: 720h0m0s
  itemOperationTimeout: 4h0m0s
  storageLocation: oadp-dpa-1
  hooks: {}
  includedNamespaces:
  - vmexamples-{user}
  snapshotMoveData: false
----

. 下部の *Create* ボタンをクリックします。
+
この YAML は、プロジェクト `vmexamples-{user}` 内のラベル `app: fedora02` を持つ全オブジェクトを、事前定義されたストレージへバックアップすることを定義しています。
+
image::2025_spring/module-05-bcdr/05_Create_Backup_YAML.png[link=self, window=blank, width=100%]

. *Status* 列が *Completed*（完了）に変わるまで待ちます。これで VM のバックアップが成功しました。
+
image::2025_summer/module-05-bcdr/06_Backup_Completed.png[link=self, window=blank, width=100%]

[[restore_backup]]
== バックアップからのリストア

. 左メニューの *Virtualization* -> *VirtualMachines* を選択し、プロジェクト `vmexamples-{user}` 内の *fedora02* VM をクリックします。
+
image::2025_spring/module-05-bcdr/07_Fedora02_Overview.png[link=self, window=blank, width=100%]

. VM を停止 (*Stop*) させます。停止後、*Actions* メニューから *Delete* を選択して VM を完全に削除します。
+
image::2025_spring/module-05-bcdr/08_Delete_VM.png[link=self, window=blank, width=100%]

. 確認画面で赤い *Delete* ボタンをクリックします。
+
image::2025_spring/module-05-bcdr/09_Confirm_Delete.png[link=self, window=blank, width=100%]

. VM が一覧から消えたことを確認してください。
+
image::2025_spring/module-05-bcdr/10_Deleted_VM.png[link=self, window=blank, width=100%]

. リストアを行うため、再度 *Operators* -> *Installed Operators* から *OADP* を選択します（プロジェクト `oadp-{user}` を選択しているか確認してください）。

. 上部タブの *Restore* を選択し、*Create Restore* ボタンをクリックします。
+
image::2025_summer/module-05-bcdr/11_Restore_Tab.png[link=self, window=blank, width=100%]

. *YAML view* に切り替え、内容を以下の定義に置き換えます：
+
[source,yaml,role=execute,subs="attributes"]
----
---
apiVersion: velero.io/v1
kind: Restore
metadata:
  name: restore-fedora02
  namespace: oadp-{user}
spec:
  backupName: backup-fedora02
  includedResources: []
  excludedResources:
  - nodes
  - events
  - events.events.k8s.io
  - backups.velero.io
  - restores.velero.io
  restorePVs: true
----

. 下部の *Create* ボタンをクリックします。
+
image::2025_spring/module-05-bcdr/12_Create_Restore_YAML.png[link=self, window=blank, width=100%]

. *Status* 列が *Completed* に変わるまで待ちます。
+
image::2025_summer/module-05-bcdr/13_Restore_Completed.png[link=self, window=blank, width=100%]

. *Virtualization* メニューに戻り、*fedora02* 仮想マシンが `vmexamples-{user}` プロジェクト内に復元されていることを確認します。作成日時を確認すると、ごく最近に復元されたものであることがわかります。
+
image::2025_spring/module-05-bcdr/14_VM_Restored.png[link=self, window=blank, width=100%]

== まとめ

仮想化プラットフォームにおいて VM のデータ保護は極めて重要です。OpenShift Virtualization では、OADP によるネイティブな保護に加え、多様なストレージ・バックアップパートナーの製品との統合が可能です。最適な保護手法については、Red Hat またはパートナーベンダーへお問い合わせください。
