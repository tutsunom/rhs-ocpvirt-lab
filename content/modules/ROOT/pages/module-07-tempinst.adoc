= テンプレートとインスタンスタイプ管理

== はじめに

事前設定された Red Hat 仮想マシンテンプレートは、*Virtualization* の *Templates* ページに一覧表示されています。これらのテンプレートは、Red Hat Enterprise Linux、Fedora、CentOS、Microsoft Windows Desktop、および Microsoft Windows Server の各バージョンで利用可能です。Red Hat 関連の各仮想マシンテンプレートは、OS イメージ（ブートソース）、OS のデフォルト設定、フレーバー（CPU とメモリ）、およびワークロードタイプ（サーバー）が事前設定されています。その他の OS 用テンプレートには OS イメージは含まれませんが、その OS に推奨される設定があらかじめ定義されています。

*Templates* ページには、以下の 4 つのタイプが表示されます：

* *Red Hat Supported*: Red Hat によって完全にサポートされています。
* *User Supported*: *Red Hat Supported* テンプレートをユーザーがクローンおよびカスタマイズしたものです。
* *Red Hat Provided*: Red Hat から限定的なサポートを受けています。
* *User Provided*: *Red Hat Provided* テンプレートをユーザーがクローンおよびカスタマイズしたものです。

[[prepare_templates_lab]]
== ラボの準備

. これから実行するタスクでは、いくつかの追加 VM をプロビジョニングする必要があります。準備として、既存の *fedora01* および *fedora02* 仮想マシンをシャットダウンし、共有環境のリソースを確保してラボを円滑に完了できるようにしてください。

. 左側のメニューから *Virtualization* 画面に移動し、*Virtualmachines* をクリックします。
. VM ワークロードが存在するプロジェクトは、中央列のツリービューに一覧表示されます（最低限、プロジェクト *vmimported-{user}* および *vmexamples-{user}* を展開して仮想マシンのステータスを確認してください）。
. いずれかの VM が *Running* ステータスの場合は、中央のツリー列で対象の VM を選択し、*Stop* ボタンまたは *Actions* ドロップダウンメニューから停止します。

これですべての VM が *Stopped* ステータスになります。

== テンプレートのクローンとカスタマイズ

デフォルトでは、Red Hat OpenShift Virtualization が提供する事前設定済みのテンプレートは編集できません。ただし、テンプレートをクローンして調整することで、エンドユーザーが特定のワークロード（データベースサーバーなど）向けの仮想マシンを簡単にリクエストできるようにカスタマイズ可能です。

. 開始するには、左側のメニューから *Templates* をクリックし、プロジェクトで *openshift* を選択します。*openshift* プロジェクトを表示するために、*Show default projects* をオンにする必要がある場合があります。
+
image::2025_spring/module-07-tempinst/01_Project_Toggle.png[link=self, window=blank, width=100%]
+
image::2025_spring/module-07-tempinst/01_Template_List.png[link=self, window=blank, width=100%]

. 検索バーに *centos9* と入力して Enter キーを押します。リストから *centos-stream9-server-small* テンプレートを探します。
+
image::2025_spring/module-07-tempinst/02_Search_Centos9.png[link=self, window=blank, width=100%]

. *centos-stream9-server-small* のテンプレート名をクリックすると、デフォルトテンプレートは編集できない旨のメッセージが表示されます。*Create a new custom Template* をクリックしてください。
+
image::2025_spring/module-07-tempinst/03_Create_Custom_Template.png[link=self, window=blank, width=100%]

. *Clone template* メニューが表示されます。以下の値を入力し、*Clone* ボタンをクリックします。
+
* *Template name:* centos-stream9-server-db-small
* *Template project:* vmexamples-{user}
* *Template display name:* CentOS Stream 9 VM - Database Template Small
* *Template provider:* Roadshow {user}
+
image::2025_spring/module-07-tempinst/04_Clone_Template_Options.png[link=self, window=blank, width=100%]

. テンプレートの *Details* ページに移動します。ページ下部の「CPU and memory」セクションにある鉛筆アイコンをクリックして編集します。
+
image::2025_spring/module-07-tempinst/05_Clone_Details.png[link=self, window=blank, width=100%]

. ポップアップウィンドウで、CPU を **2** に、メモリを **4 GiB** に設定し、*Save* をクリックします。
+
image::2025_spring/module-07-tempinst/06_Edit_CPU_Mem.png[link=self, window=blank, width=100%]

. 上部の *Scripts* タブをクリックし、*Cloud-init* セクションの *Edit* をクリックします。
+
image::2025_spring/module-07-tempinst/09_Scripts_CloudInit.png[link=self, window=blank, width=100%]

. *Cloud-init* ダイアログが開いたら、*Configure via: Script* を選択し、YAML 内容を以下のスニペットに**置き換えます**。
+
[source,yaml,role=execute]
----
userData: |-
  #cloud-config
  user: centos
  password: ${CLOUD_USER_PASSWORD}
  chpasswd: { expire: False }
  packages:
    - mariadb-server
  runcmd:
    - systemctl enable mariadb
    - systemctl start mariadb
----
+
image::2025_spring/module-07-tempinst/10_Cloud_Init_Script.png[link=self, window=blank, width=100%]

. *Save* をクリックし、緑色の *Saved* という通知が表示されたら、*Apply* をクリックします。

. 左側のメニューで *Catalog* をクリックし、*Template catalog* タブから *User templates* を選択します。作成したテンプレートがタイルとして表示されていることを確認してください。
+
image::2025_spring/module-07-tempinst/11_User_Templates.png[link=self, window=blank, width=100%]

. タイルをクリックし、*Quick create VirtualMachine* ボタンで VM を作成します。
+
image::2025_spring/module-07-tempinst/12_Quick_Create_Template.png[link=self, window=blank, width=100%]

. 起動後、*Overview* ページでリソース設定が反映されていることを確認します。次に MariaDB がインストールされているか確認します。
+
image::2025_spring/module-07-tempinst/13_VM_From_Template.png[link=self, window=blank, width=100%]

. *Console* タブをクリックし、表示されている *Guest login credentials* を使用してログインします。
+
image::2025_spring/module-07-tempinst/14_VM_Console.png[link=self, window=blank, width=100%]

. ログイン後、以下のコマンドで MariaDB のインストールを確認します。
+
[source,sh,role=execute]
----
sudo mysql -u root
----
+
image::2025_spring/module-07-tempinst/15_MariaDB_Login.png[link=self, window=blank, width=100%]

. *Ctrl-D* を 2 回押してログアウトします。

== Windows VM テンプレートの作成

ここでは、Web サーバー上の ISO イメージを使用して Microsoft Windows Server 2019 をインストールします。これは、さまざまな場所（Web サーバー、オブジェクトストレージ、クラスター内の永続ボリュームなど）からディスクをソースとして利用できる機能の一例です。

初期インストール後、Sysprep 済みの仮想マシンからルートディスクをクローンして他のテンプレートで利用できるようにすることで、構築プロセスを効率化できます。

注：ゲスト OS の準備プロセスは OS によって異なります。テンプレート用の OS を準備する際は、組織のガイドラインに従ってください。

. 左側メニューの *Catalog* から *Template catalog* タブをクリックします。

. *win* で検索するか、*Microsoft Windows Server 2019 VM* タイルを探します。
+
image::2025_spring/module-07-tempinst/16_Windows_2k19_Tile.png[link=self, window=blank, width=100%]

. テンプレートのデフォルト設定を示すダイアログが表示されます。ブートソースが未設定のため、初期状態では「クイック作成」はできません。
+
image::2025_spring/module-07-tempinst/17_Windows_2k19_Dialog.png[link=self, window=blank, width=100%]

. このダイアログで以下の設定を入力します。
* 名前: *win-sysprep*
* *Boot from CD* を有効化
* *URL (creates PVC)* を選択
* image URL: `https://catalog-item-assets.s3.us-east-2.amazonaws.com/qcow_images/Windows2019.iso`
* CD ディスクサイズ: *5 GiB* に縮小
* *Disk source*: *Blank*、サイズ: *60 GiB*（デフォルト）
* *Mount Windows drivers disk* を有効化（Windows インストールに必須の VirtIO ドライバーを提供します）

. オプションの入力が終わったら、下部の *Customize VirtualMachine* ボタンをクリックして設定を続けます。
+
image::2025_spring/module-07-tempinst/18_Windows_2k19_Parameters.png[link=self, window=blank, width=100%]

. *Customize and create VirtualMachine* 画面で、*Boot mode* の鉛筆アイコンをクリックします。
+
image::2025_spring/module-07-tempinst/19_Boot_Mode.png[link=self, window=blank, width=100%]

. ドロップダウンから **BIOS** を選択し、*Save* をクリックします。
+
image::2025_spring/module-07-tempinst/19a_Boot_BIOS.png[link=self, window=blank, width=100%]

. *Scripts* タブの *Sysprep* セクションで *Edit* をクリックします。
+
image::2025_spring/module-07-tempinst/20_Customize_Scripts.png[link=self, window=blank, width=100%]

. 以下のコードを *autounattend.xml* セクションに貼り付けます。これは Windows のインストールと初期設定を自動化します。

[[instance_types]]
== インスタンスタイプの概要

インスタンスタイプは、リソース定義（CPU/メモリ）を再利用可能なオブジェクトとして定義したものです。パブリッククラウドのようなセルフサービス体験を提供できます。

. 左側メニューの *Catalog* をクリックします。デフォルトのカタログアイテムは *InstanceType* です。
. まずブートソース（例：*rhel9*）を選択します。
. 次に使用するインスタンスタイプを選択します。*U series*（汎用）の **medium (1 CPUs, 4 GiB Memory)** などを選択し、*Create VirtualMachine* を実行します。
+
* Red Hat 提供の主なシリーズ：
** *N series*: ネットワーク集約型ワークロード向け
** *O series*: メモリオーバーコミット設定済みの汎用
** *CX series*: コンピューティング集約型ワークロード向け
** *U series*: 最も汎用的な「ユニバーサル」タイプ
** *M series*: メモリ集約型ワークロード向け

[[cleanup]]
== クリーンアップ

次のラボのためにリソースを節約するため、このモジュールで作成した VM をすべて停止してください。

. 左側のメニューから *Virtualization* > *Virtualmachines* に移動します。
. VM ワークロードが存在する各プロジェクト（*vmimported-{user}* および *vmexamples-{user}* など）を確認します。
. 実行中の VM を選択し、*Stop* ボタンで停止してください。

これですべての VM が *Stopped* ステータスになります。

image::2025_spring/module-07-tempinst/40_All_Stopped.png[link=self, window=blank, width=100%]
