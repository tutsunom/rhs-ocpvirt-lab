= テンプレートとインスタンスタイプ管理

== はじめに

事前設定されたRed Hat仮想マシンテンプレートは、*Virtualization*の*Templates*ページに一覧表示されています。これらのテンプレートは、Red Hat Enterprise Linux、Fedora、CentOS、Microsoft Windows Desktop、およびMicrosoft Windows Serverの異なるバージョンで利用可能です。各Red Hatに関連する仮想マシンテンプレートは、オペレーティングシステムイメージ(ブートソース)、オペレーティングシステムのデフォルト設定、フレーバー(CPUとメモリ)、およびワークロードタイプ(サーバー)で事前設定されています。他のオペレーティングシステム用のテンプレートはOSイメージを含みませんが、そのオペレーティングシステムに推奨されるように事前設定されています。

*Templates*ページには、4つのタイプの仮想マシンテンプレートが表示されます：

* *Red Hat Supported*テンプレートはRed Hatによって完全にサポートされています。
* *User Supported*テンプレートは、ユーザーによってクローンされおよびカスタマイズされた*Red Hat Supported*テンプレートです。
* *Red Hat Provided*テンプレートはRed Hatから限定的なサポートを受けています。
* *User Provided*テンプレートは、ユーザーによってクローンされおよびカスタマイズされた*Red Hat Provided*テンプレートです。

== ラボの準備

. これから実行するタスクでは、いくつかの追加VMをプロビジョニングする必要があります。準備として、既存の*fedora01*および*fedora02*仮想マシンをシャットダウンして、共有環境にラボを完了するための十分なリソースがあることを確認することをお願いします。

. 左側のメニューから*Virtualization*パースペクティブに移動し、*Virtualmachines*をクリックします。
. アクセス権を持つ各プロジェクトがVMワークロードをホストしている場合、中央の列のツリービューに一覧表示されます。(最低でも、プロジェクト*vmimported-{user}*および*vmexamples-{user}*を展開して仮想マシンのステータスを確認する必要があります。)
. いずれかのVMが*Running*ステータスを表示している場合は、中央のツリー列でVMをハイライトし、*Stop*ボタンまたは*Actions*ドロップダウンメニューのオプションを選択します。

これですべてのVMが*Stopped*ステータスになります。

== テンプレートのクローンとカスタマイズ

デフォルトでは、Red Hat OpenShift Virtualizationによって提供される事前設定されたテンプレートはカスタマイズできません。ただし、テンプレートをクローンして調整して特定のワークロード用に対応させることで、エンドユーザーが特定のワークロード用の特定のタイプの仮想マシンをリクエストしやすくすることができます。ラボのこのセクションでは、オンデマンドで事前設定されたデータベースサーバーを提供するテンプレートを作成することでこれを行います。

. 開始するには、左側のメニューから*Templates*をクリックし、プロジェクトの*openshift*を選択します。*openshift*プロジェクトが表示されるようにするために、*Show default projects*ボタンをトグルする必要があるかもしれません。

+
image::2025_spring/module-07-tempinst/01_Template_List.png[link=self, window=blank, width=100%]

. 検索バーに*centos9*と入力してEnterキーを押します。表示されるテンプレートのリストで*centos-stream9-server-small*のテンプレートを見つけます。
+
image::2025_spring/module-07-tempinst/02_Search_Centos9.png[link=self, window=blank, width=100%]

. *centos-stream9-server-small*のテンプレート名をクリックすると、デフォルトテンプレートは編集できず、クローンするよう求めるメッセージが表示されます。*Create a new custom Template*オプションをクリックします。
+
image::2025_spring/module-07-tempinst/03_Create_Custom_Template.png[link=self, window=blank, width=100%]

. *Clone template*という新しいメニューが表示されます。以下の値を入力し、完了したら*Clone*ボタンをクリックします。

image::2025_spring/module-07-tempinst/04_Clone_Template_Options.png[link=self, window=blank, width=100%]

. これにより、テンプレートの*Details*ページに移動します。ここでいくつかのオプションをカスタマイズできます。ページの下部にあるCPUとメモリを見つけて、鉛筆アイコンをクリックして編集します。

. CPUとメモリの量を編集できる新しいウィンドウがポップアップされます。カスタムテンプレートの場合、CPUの値を2に、メモリを4 GiBに設定し、*Save*ボタンをクリックします。

image::2025_spring/module-07-tempinst/06_Edit_CPU_Mem.png[link=self, window=blank, width=100%]

image::2025_spring/module-07-tempinst/09_Scripts_CloudInit.png[link=self, window=blank, width=100%]

== Windows VMテンプレートの作成

ラボのこのセグメントでは、Webサーバーでホストされているイメージを使用してMicrosoft Windows Server 2019をインストールします。これは、多くの場所(Webサーバー、オブジェクトストレージ、またはクラスター内の他の永続ボリュームを含む)からディスクをソースできる機能を利用するオペレーティングシステムをインストールする方法の1つを表します。

初期のオペレーティングシステムインストール後、sysprepped仮想マシンからの複製ルートディスクを作成して、他のテンプレートで使用できるようにすることで、このプロセスを合理化できます。

注：ゲストオペレーティングシステムを準備してテンプレートとして使用するための具体的なプロセスは異なります。テンプレートOSを準備する際は、組織のガイドラインと要件に従うようにしてください。

. 左側のメニューから*Catalog*に移動し、上部の*Template catalog*タブをクリックします。

. 検索バーに単語*win*を入力するか、*Microsoft Windows Server 2019 VM*タイルが見つかるまでスクロールダウンします。
+
image::2025_spring/module-07-tempinst/16_Windows_2k19_Tile.png[link=self, window=blank, width=100%]

. テンプレートに関連するデフォルト設定を示すダイアログが表示されます。
+
注：このテンプレートのブートソースが提供されていないため、初期状態ではこのVMをクイック作成するオプションはないことに注意してください。ニーズに合わせてVMをカスタマイズする必要があります。
+
image::2025_spring/module-07-tempinst/17_Windows_2k19_Dialog.png[link=self, window=blank, width=100%]
+
. このダイアログで:
* 名前*win-sysprep*を指定します
* *Boot from CD*チェックボックスを有効にします
* ドロップダウンメニューから*URL (creates PVC)*を選択します
* *image URL*を指定します: https://catalog-item-assets.s3.us-east-2.amazonaws.com/qcow_images/Windows2019.iso
* CDディスクサイズを*5 GiB*に削減します
* *Disk source*を*Blank*として保持し、サイズをデフォルト値*60 GiB*のままにします
* *Mount Windows drivers disk*チェックボックスが有効になっていることを確認します。**これはWindowsシステムをインストールするために必須であり、VirtIOのドライバーを提供します。**

. オプションが入力されたら、下部の*Customize VirtualMachine*ボタンをクリックして、テンプレートの設定を続行します。

image::2025_spring/module-07-tempinst/18_Windows_2k19_Parameters.png[link=self, window=blank, width=100%]

[[instance_types]]
== インスタンスタイプの概要

インスタンスタイプは、新しいVMを作成するときに適用するリソースと特性を定義できる再利用可能なオブジェクトです。
OpenShiftVirtualizationをインストールするときに含まれるカスタムインスタンスタイプまたはさまざまなものを定義できます。
これは、一般的なクラウドプロバイダーのセルフサービスカタログを使用するときにユーザーが経験することに非常に似ています。

このセクションでは、インスタンスタイプを使用したVMのプロビジョニングについて説明しています。

. 開始するには、左側のメニューから*Catalog*をクリックします。デフォルトカタログアイテムは*InstanceType*です。
+
image::2025_spring/module-07-tempinst/33_Left_Menu_Catalog.png[link=self, window=blank, width=100%]

. インスタンスタイプを使用する最初のステップは、ブートするボリュームを選択することです。ブートソースを提供するテンプレートと同様に、これらのブートソースはInstanceTypeでプロビジョニングされたゲストで使用可能です。*openshift-virtualization-os-images*プロジェクトを選択することで含まれているボリュームを確認できるか、*Add volume*ボタンで独自のボリュームをアップロードできます。
+
image::2025_spring/module-07-tempinst/34_Volume_Boot.png[link=self, window=blank, width=100%]

. ブートソースとして使用するボリュームタイプを選択するには、*rhel9*ブートボリュームをクリックします。選択すると、イメージ名の左側に小さい縦の青い線が付き、名前自体が太字フォントに変わります。
+
image::2025_spring/module-07-tempinst/35_Select_RHEL9.png[link=self, window=blank, width=100%]

. 次に、使用するインスタンスタイプを選択できます。
Red Hatが提供するデフォルトのインスタンスタイプがあるか、特定のユースケース用に独自のものを作成できます。
提供されるインスタンスタイプの上にマウスを移動すると、その意図された使用の説明が表示されます。
+

== クリーンアップ

次のラボのためにリソースを節約するため、このモジュールで作成したVMをすべて停止してください。

. 左側のメニューから*Virtualization*パースペクティブに移動し、*Virtualmachines*をクリックします。
. アクセス権を持つ各プロジェクトがVMワークロードをホストしている場合は、中央の列のツリービューに一覧表示されます。(最低でも、プロジェクト*vmimported-{user}*および*vmexamples-{user}*を展開して仮想マシンのステータスを確認する必要があります。)
. いずれかのVMが*Running*ステータスを表示している場合は、中央のツリー列でVMをハイライトし、*Stop*ボタンまたは*Actions*ドロップダウンメニューのオプションを選択します。

これですべてのVMが*Stopped*ステータスになります。

== まとめ

このセクションでは、既存のテンプレートをクローンしてカスタマイズし、データベースのような特定のワークロード用に使用できるものを作成する方法を学びました。また、ブートソースなしで存在する既存のWindowsテンプレートの1つを設定し、そのインストールプロセスを自動化する方法も学びました。そのため、そのVMで作成されたインストールPVCをクローンすることで、将来のデプロイメントを簡単に作成できます。また、特定のワークロード用に仮想マシンをさらにカスタマイズして、より クラウドのような体験を提供するためにインスタンスタイプを利用する方法についても紹介しました。
