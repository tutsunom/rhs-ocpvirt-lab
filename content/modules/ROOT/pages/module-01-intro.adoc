= 仮想マシン管理

== はじめに

このラボの最初のセクションでは、OpenShift Virtualization で仮想マシン（VM）を作成および管理するための基本を学びます。OpenShift 4.18 以降、VM の可視化と管理を容易にする新しい「仮想化パースペクティブ」と「ツリービュー」が導入されました。UI の変更点を確認した後、Web コンソールに用意されたテンプレートから VM を作成する一連のプロセスを学習します。その後、VM のプロパティ確認や基本的なカスタマイズを行い、ライブマイグレーションなど、仮想マシン管理者が通常行うアクションを実行します。

.*目標*

* 新しい仮想マシンを作成する
* 仮想マシンのリソースを確認および変更する
* OpenShift コンソールを使用して VM の電源状態を管理する方法を理解する
* ホスト間で VM をライブマイグレーションする

参考までに、OpenShift コンソールの認証情報は以下の通りです。

OpenShift クラスターコンソールは {openshift_console_url}[こちら^] からアクセス可能です。

ログイン情報は以下の通りです：

* *ユーザー:* {user}
* *パスワード:* {password}

[[create_project]]
== 新しいプロジェクトの作成

. VM を作成する前に、新しいプロジェクトを作成する必要があります。仮想マシンは特定のプロジェクトにデプロイされ、権限のないユーザーはその VM を管理できません。管理者はすべてのプロジェクトを表示できますが、一般ユーザーは必要に応じてプロジェクトへのアクセス権を付与される必要があります。
+
. 中央のツリービューセクションの右上にある *プロジェクトを作成* をクリックします。
+
image::2025_spring/module-01-intro/10_Column_Create.png[link=self, window=blank, width=100%]

. *名前* フィールドに *vmexamples-{user}* と入力して、*作成* をクリックします。
+
image::2025_spring/module-01-intro/11_Create_Project.png[link=self, window=blank, width=100%]
+
NOTE: 仮想マシン一覧のセクションはすぐにこの新しいプロジェクトを表示するように切り替わりますが、プロジェクト内に VM がまだ存在しないため、中央のツリービューにはすぐには反映されない場合があります。


[[create_vm]]
== Linux 仮想マシンの作成

. 仮想マシン一覧セクションの *仮想マシンを作成* ボタンをクリックし、ドロップダウンから *テンプレートから* を選択します。
+
NOTE: VM はウィザードや YAML 定義からも作成可能ですが、このラボでは既存のテンプレートを使用します。
+
image::2025_spring/module-01-intro/12_Create_VM_Button.png[link=self, window=blank, width=100%]

. *カタログ* 画面に、利用可能な VM テンプレートがタイル状に表示されます。
+
青いバッジがついているテンプレートは「ソースが利用可能」であることを示しており、テンプレート用のディスクソースが既にダウンロード済みであることを意味します。
+
組織のニーズに合わせてテンプレートをカスタマイズしたり、独自のディスクイメージを使用することも可能です。
+
image::2025_spring/module-01-intro/13_Create_VM_Templates.png[link=self, window=blank, width=100%]

. *Fedora VM* タイルを選択すると、ダイアログが開きます。
+
image::2025_spring/module-01-intro/14_Create_VM_Quick.png[link=self, window=blank, width=100%]

. 名前を *fedora01* に変更して、*仮想マシンをすばやく作成* をクリックします。
+
image::2025_spring/module-01-intro/15_Create_VM_Quick_Name.png[link=self, window=blank, width=100%]

. ツリービューに戻ると、新しい VM の情報が表示されます。また、*vmexamples-{user}* プロジェクトに VM が作成されたため、中央のセクションにもプロジェクトが表示され、ハイライトされます。
+
VM のステータスが *プロビジョニング* から *起動中*、最終的に *実行中* へと変化するのを確認してください。
+
この間に、ストレージプロバイダーはテンプレートディスクをクローンしています。この処理にかかる時間は、使用しているストレージの性能やシステムの負荷によって異なります。
+
image::2025_spring/module-01-intro/16_Fedora_Running.png[link=self, window=blank, width=100%]

. VM が起動したら、右側のセクションの *概要* ページで詳細を確認できます。
+
* *詳細*: VM 名、ステータス、OS、リソース構成、使用したテンプレートなどが表示されます。また、VNC ターミナルの起動もここから行えます。
* *一般*: プロジェクト名、インスタンス名、およびゲストを実行している Pod 名など、OpenShift 固有の情報が表示されます。
* *スナップショット*: スナップショットの作成や履歴の確認ができます。
* *ネットワーク*: IP アドレスと内部ホスト名が表示されます。デフォルトでは Pod ネットワークに接続されます。
* *使用率*: CPU、メモリ、ストレージ、ネットワークのリアルタイムな使用状況が表示されます。
+
image::2025_spring/module-01-intro/17_Fedora_Details.png[link=self, window=blank, width=100%]

. 詳細の確認が終わったら、*イベント* タブをクリックしてプロビジョニングのログを確認します。作成時にエラーが発生した際も、ここから原因を特定できます。主なイベントは以下の通りです：
+
image::2025_spring/module-01-intro/18_Fedora_Events.png[link=self, window=blank, width=100%]
+
* _DataVolume_ の作成：VM ディスクのクローンやインポート処理が行われます。
* 新しい _VM インスタンス_ (fedora01) の起動。

[[admin_vms]]
== 仮想マシンの管理

仮想マシンの管理には、作成だけでなく、リソースの調整や状態の制御、ノード間でのライブマイグレーションなどが含まれます。

. *構成* タブをクリックします。ここが VM リソースの変更や詳細設定のエントリポイントとなります。
+
image::2025_spring/module-01-intro/19_VM_Configuration.png[link=self, window=blank, width=100%]
+
構成タブには 7 つのサブタブがあります：
+
image::2025_spring/module-01-intro/20_Configuration_Tab.png[link=self, window=blank, width=100%]
+
* *詳細*: CPU/メモリの変更、ホスト名の設定、デバイスのパススルー、ブート順序などを一括で編集できます。
* *ストレージ*: ディスクの管理や新規追加を行います。ConfigMap や Secret をディスクとしてアタッチし、VM 内のアプリに設定データを渡すことも可能です。
* *ネットワーク*: ネットワークインターフェイスの確認や追加を行います。
* *スケジューリング*: アフィニティルールやノードセレクター、エビクション戦略など、VM がどのノードで実行されるかを制御します。
* *SSH*: 公開鍵の注入や SSH サービスの設定を行い、リモートアクセスを構成します。
* *初期実行*: _cloud-init_ (Linux) や _sysprep_ (Windows) を使用して、初回起動時のセットアップ（アプリインストール等）を構成します。
* *メタデータ*: ラベルや注釈（Annotation）を管理し、自動化ワークフローなどに活用します。

. 各項目を確認してください。ここでは特に関連性の高いストレージとネットワークに焦点を当てます。

. *ストレージ* タブをクリックします。
+
image::2025_spring/module-01-intro/21_Storage_Tab.png[link=self, window=blank, width=100%]
+
この環境では、デフォルトの StorageClass として OpenShift Data Foundation (ODF) が提供する *ocs-storagecluster-ceph-rbd-virtualization* が使用されています。

. *ネットワーク* サブタブをクリックします。
+
image::2025_spring/module-01-intro/22_Network_Tab.png[link=self, window=blank, width=100%]
+
デフォルトでは、*マスカレード* モードの *Pod ネットワーク* インターフェイスが作成されます。これにより VM は外部への通信が可能になり、クラスター内の他の VM や Pod からもアクセスできるようになります。

[[vm_state]]
== 仮想マシンの状態制御

Web コンソールから VM の停止、起動、再起動、一時停止などの操作が可能です。

. *概要* タブに戻ります。

. 右上隅に、停止、再起動、一時停止、開始のショートカットボタンと、*アクション* メニューがあります。
+
image::2025_spring/module-01-intro/23_VM_State_Actions.png[link=self, window=blank, width=100%]
+
* *停止*: 仮想マシンのシャットダウンを実行します。
* *再起動*: OS に再起動シグナルを送ります（ゲストエージェントが必要です）。
* *一時停止*: メモリの状態を維持したまま、CPU と I/O へのアクセスを凍結します。
* *開始*: 停止している VM を起動します。

. *アクション* メニューからも、これらの操作やその他の高度なオプションにアクセスできます。
+
image::2025_spring/module-01-intro/24_VM_Actions_Menu.png[link=self, window=blank, width=100%]

. *停止* をクリックし、ステータスが *停止* になるまで待ちます。
+
image::2025_spring/module-01-intro/25_VM_Stopped.png[link=self, window=blank, width=100%]

. VM が停止すると、*開始* 以外の操作（再起動や一時停止など）はグレーアウトされます。
+
image::2025_spring/module-01-intro/26_VM_Actions_List_Stopped.png[link=self, window=blank, width=100%]

. *開始* をクリックして、ステータスを *実行中* に戻します。

. *一時停止* を試してみましょう。ステータスが *一時停止* に変わります。
+
image::2025_spring/module-01-intro/27_VM_Actions_Paused.png[link=self, window=blank, width=100%]

. *再開* をクリックして、VM を元の状態に戻します。

[[live_migrate]]
== 仮想マシンのライブマイグレーション

VM を停止させずに、実行中のノードから別のノードへ移動させます。これには *ReadWriteMany* (RWX) ストレージが必要です。OpenShift Virtualization では、各 VM ディスクは独立したボリュームに保存され、必要なノードにのみマウントされます。

. VM が現在実行されている物理ノードを確認します。*概要* ページの *一般* セクションにある Pod 名（virt-launcher-fedora01-xxxx）をクリックします。
+
image::2025_spring/module-01-intro/28_Pod_Name.png[link=self, window=blank, width=100%]

. Pod の詳細ページで、*ノード* の項目を確認します。例では _worker-cluster-ttgmt-3_ で実行されています。
+
image::2025_spring/module-01-intro/29_Pod_Details_Node.png[link=self, window=blank, width=100%]

. ブラウザの「戻る」で *概要* ページに戻ります。

. *アクション* メニューから、*マイグレーション* -> *コンピュート* を選択します。
+
image::2025_spring/module-01-intro/30_VM_Dialog_Migrate.png[link=self, window=blank, width=100%]

. ステータスが *マイグレーション* に変わり、進捗が表示されます。
+
image::2025_spring/module-01-intro/31_VM_Migrating.png[link=self, window=blank, width=100%]

. 完了後、ステータスが *実行中* に戻ります。再度 Pod 名をクリックして、実行ノードを確認してください。
+
image::2025_spring/module-01-intro/32_Migrated_Status.png[link=self, window=blank, width=100%]

. ノード名（例: _worker-cluster-ttgmt-2_）が変わっていることが確認できます。ライブマイグレーションにより、VM インスタンスは新しいノード上の新しい Pod へと無停止で転送されました。
+
image::2025_spring/module-01-intro/33_Pod_Details_Node_Migrated.png[link=self, window=blank, width=100%]

== まとめ

このラボでは、OpenShift Virtualization の管理環境の概要を確認し、テンプレートからのプロビジョニング、電源操作、およびライブマイグレーションの手順を学びました。これらはプラットフォーム管理者にとって必須のスキルであり、OpenShift 上で VM を運用する際の基礎となります。
